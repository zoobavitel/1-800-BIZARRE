# frontend/

This directory contains the React-based frontend application for the 1-800-BIZARRE platform. It is responsible for providing the user interface, interacting with the backend API, and presenting game data to the users.

## Purpose

The primary purpose of this directory is to:

- **Render the User Interface**: Display character sheets, campaign information, game mechanics, and other interactive elements.
- **Consume Backend APIs**: Make requests to the backend to fetch and update game data.
- **Manage User Interaction**: Handle user input, navigation, and real-time updates to the character sheets and game state.
- **Provide a Rich User Experience**: Offer an intuitive and engaging interface for players and Game Masters.

## Key Contents

- `public/`: Static assets served as-is (`index.html`, `favicon.ico`, `manifest.json`, `media/`, and a copy of the SRD under `srd/`).
- `src/`: React application source. Notable subfolders: `pages/`, `components/`, `features/`, `layouts/`, `services/`, `data/`, `config/`, `utils/`, `lib/`, `styles/`, `assets/`, `integration/`.
- `scripts/`: Build-time helpers run via `pre*` npm scripts — `generatePatchNotes.js` (builds `src/data/patchNotes.js` from git history) and `copySrd.js` / `splitSrd.js` (publishes the SRD into `public/srd/`).
- `e2e/` and `playwright.config.js`: Playwright end-to-end smoke tests.
- `package.json`, `package-lock.json`: Node.js project metadata and dependencies.
- `tailwind.config.js`, `postcss.config.js`: Tailwind CSS and PostCSS configuration.
- `craco.config.js`: CRACO override hook for the CRA build (currently a no-op placeholder).
- `.env`, `.env.production`: Environment variables for development and production builds.
- `nginx.conf`: Nginx configuration used when serving the production bundle behind a reverse proxy.
- `README.md`: This file.

## Tooling

- **Build / dev server**: [Create React App](https://create-react-app.dev/) via `react-scripts` 5 (webpack under the hood). Run with `npm start` / `npm run build` / `npm test`. `npm run test:coverage` runs Jest once with coverage.
- **Routing**: `react-router-dom` v7.
- **Styling**: Tailwind CSS (utility-first) with PostCSS + Autoprefixer.
- **UI bits**: `lucide-react` (icons), `react-burger-menu` (mobile nav), `react-markdown` (SRD / patch-note rendering), `recharts` (charts).
- **Testing**: Jest + React Testing Library (unit/component) and Playwright (`npm exec playwright test`) for browser E2E.
- **Deploy target**: Static bundle served from `build/`. Production homepage is configured for GitHub Pages (`https://zoobavitel.github.io/1-800-BIZARRE`); `nginx.conf` covers self-hosted deployments.

## Code Quality and Structure

The frontend follows a standard React project structure, promoting:

- **Component-Based Architecture**: UI is broken down into reusable components, enhancing modularity and maintainability.
- **Feature folders**: Larger flows (e.g. character sheet) live under `src/features/<feature>/` with their own `components/`, `constants/`, and helpers, keeping page-level files thin.
- **Clear Separation of Concerns**: UI logic is kept distinct from API interaction (`src/services/`) and shared state/data (`src/data/`, `src/config/`).
- **Build-time data generation**: SRD content and patch notes are generated by `scripts/` during `prestart`/`prebuild`, so the running app ships with up-to-date docs without manual copying.

## Logic Behind Decisions

- **React** was chosen for its mature ecosystem and component model, which fits a data-heavy character sheet / campaign UI.
- **Create React App + CRACO** was kept (rather than migrating to Vite) because the existing test, ESLint, and PostCSS pipeline already works and the bundle size is not currently a bottleneck. CRACO is wired up so the CRA webpack config can be overridden without ejecting.
- **Tailwind CSS** is used for utility-first styling so per-component CSS stays minimal and visual consistency is easier to enforce.
- **Playwright** handles end-to-end smoke testing in a real browser, complementing Jest unit tests.
- **GitHub Pages** is the default static host so the frontend can be demoed without infrastructure; `nginx.conf` exists for self-hosted deployments where the API is on the same origin.
